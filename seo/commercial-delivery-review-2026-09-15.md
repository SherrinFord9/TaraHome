# Commercial image delivery review: September 15, 2026

## Finding and change

Thirteen commercial pages and eight related guides still delivered their hero
artwork as 1.46-2.09 MB PNGs. The previously optimized starter-kit page was not
affected. The 21 affected URLs and nine source assets are listed in
`seo/commercial-images.json`.

Delivery commit: `cebcdb34b734433565a1bb6abeb5e0c35947b4e1`.
[GitHub Pages deployment succeeded](https://github.com/SherrinFord9/TaraHome/actions/runs/35006788945).

Each affected hero now uses responsive WebP candidates, an explicit `sizes`
attribute, intrinsic dimensions, eager loading, async decoding, and high fetch
priority. Existing matching derivatives were reused for six source images;
Pillow generated 640px and 1280px derivatives for the three documentation images.
No artwork was replaced or newly generated by AI. Original PNGs, social images,
and schema image URLs remain intact.

Only the hero img attributes changed in each HTML document. A parsed comparison
against `85ff400ef659e841bcbdbe8935e656d6b792f7cc` verified the rest of all 21
documents, including complete heads, copy, styles, and schema, was identical.
Homepage, configurator, library indexes, fonts, sitemap, llms metadata, and all
original PNGs have no diff from that commit. No publication dates were advanced.

## Controlled live measurements

Both phases used `https://tarahome.ai`, Chromium, three cold loads per page,
390x844 at DPR 1, cache disabled, fresh browser contexts, 150ms network latency,
200,000 bytes/s download throughput, and 4x CPU slowdown. Analytics and forms
were blocked in the test contexts. These are synthetic measurements, not
Lighthouse scores or field Core Web Vitals.

| Page | Hero bytes before / after | Reduction | Median image response end before / after |
| --- | --- | --- | --- |
| `/smart-home-kit/` | 1,901,442 / 13,884 | 99.27% | 10.09s / 0.59s |
| `/camera-kit/` | 2,088,183 / 27,600 | 98.68% | 11.01s / 0.70s |
| `/home-assistant-smart-home-kit/` | 1,795,278 / 16,964 | 99.06% | 9.54s / 0.61s |

Times are measured from navigation start, not isolated network request duration.
The H1 was the LCP element in every sample. LCP medians were 416/408ms,
392/388ms, and 396/416ms respectively: no material LCP improvement is claimed.
No layout-shift entries were observed during these loads; this does not establish
a field CLS score. Full samples and conditions are in
`seo/commercial-loading-2026-09-15.json`; the reusable measurement script is
`scripts/measure-commercial-loading.browser.js`.

Responsive delivery lets the browser choose an appropriate image size; it is not
a redesign. This follows [responsive-image guidance](https://web.dev/articles/serve-responsive-images).
The distinction between image download time and the actual LCP element follows
[Chrome's LCP guidance](https://web.dev/articles/optimize-lcp).

## Verification and publishing protection

- 72 local and 72 live browser cases passed. All 21 pages were checked at 1440px
  and 390px; nine artwork representatives at 360px DPR 3 and 820/821px DPR 2;
  three representative pages at 390px without page JavaScript.
- Images decoded, retained the 16:9 frame and cover crop, and did not overlap the
  H1 or overflow horizontally. Representative screenshots were visually reviewed.
  Nine keyboard navigation checks per run reached the configurator. No inquiry
  was submitted. Test contexts reported no page errors.
- Live HTML for all 21 pages, plus homepage, configurator, library index and
  sitemap, matched the production worktree byte for byte.
- Eight image regression tests, nine runner tests, and thirteen SEO-intent tests
  passed. The protected intent, typography, layout, editorial-copy, cover-quality,
  and whitespace gates passed.
- The daily runner now runs `check-commercial-images.py` before publishing.
  It rejects missing/oversized derivatives, invalid formats or declared widths,
  missing source assets, and reverted hero delivery attributes. The writer prompt
  explicitly forbids regenerating these pages. The existing isolated scope check
  still prohibits a daily article from editing them or the configurator.
- To check manually: `uv run --with 'pillow>=11,<13' scripts/check-commercial-images.py`.
  `--generate-missing` only encodes missing derivatives; it never rewrites HTML or
  replaces existing assets. Any future intentional artwork/layout change must
  update the manifest and be reviewed in the browser.
