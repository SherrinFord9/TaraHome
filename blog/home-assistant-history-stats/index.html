Home Assistant History Stats: Track Daily Device Runtime

See how long a lamp or sensor was on today, check the total, and understand what recorded runtime can—and cannot—tell you.

By Tara Home

TLDR

  • Use the built-in History Stats helper, with Type set to Time. It adds together the periods when a selected device reported the state you chose.
  • For today, use local midnight as Start and now as End. Leave Duration empty. “Today” and “the last 24 hours” are different questions.
  • Choose what you actually want to measure. A plug being on means its outlet is enabled; it does not prove the connected appliance is working.
  • Check with a harmless Toggle helper first. Six recorded minutes on should add about 0.10 hours. Missing history and stale device reports limit the result.

Researched from current Home Assistant documentation and Core 2026.10.1 source on October 11, 2026. The timeline below is a calculated example, not a measured Tara installation. No device or live Home Assistant installation was tested for this guide. Menu labels can differ on older releases.

Add up the on-time, without building a timer automation

Home Assistant History Stats is the simplest built-in starting point for “How long was this lamp on today?” Create a helper—a value calculated inside Home Assistant—that watches the lamp’s recorded on state. It can combine several separate sessions into one daily total.

You need an existing device that reports its state, plus retained history for that device. You do not need a new timer, a paid service, or a custom integration. Start with a lamp whose on/off status already looks right in Home Assistant, and display its total before using it in any automation. The History Stats documentation describes the available helper settings.

This measures reported state over time. It does not independently watch the bulb, measure electricity, or turn anything off. If your actual question is “stop something after ten minutes,” use the separate countdown and restart guide. A daily runtime display answers what happened, rather than scheduling a future action.

1. Choose a state that means the right thing

An entity is a named item in Home Assistant, such as light.reading_lamp. Open Settings → Tools → States, or Developer tools → States on older releases, and read its stored state. Use this screen to inspect; do not use Set state as a device test. The Tools documentation explains that changing a displayed state does not command the physical device.

If the integration does not report activity, this lamp recipe cannot establish burner or compressor runtime.

2. Create the daily runtime helper

  1. Open History and select the source entity. Check that today’s on and off periods appear. A current on/off reading alone does not prove that earlier changes were saved. See the History instructions if your panel is empty.
  2. Go to Settings → Devices & services → Helpers → Create helper → History Stats.
  3. Name it Reading lamp on today, select your lamp, and choose Time. Select the state corresponding to on.
  4. In the period options, enter the settings below. Expand Additional settings to check Minimum state duration. Home Assistant may spread these fields across several dialogs.
  5. Save, then add the new sensor to an editable dashboard. An Entities card can show the lamp and its runtime together.

State class tells Home Assistant how to store statistics about a sensor; it does not change which device state you count. Choose it when creating this new helper. The fields above are supported by the 2026.10.1 helper configuration.

For a rolling 24-hour view, create a separate helper: leave Start empty, use {{ now() }} for End, set Duration to 24 hours, and choose Measurement as its state class. That moving total can fall as yesterday’s sessions leave the window. The today_at reference explains local time; a local calendar day is not always exactly 24 elapsed hours when clocks change.

3. Check a whole day, including the midnight boundary

Imagine these recorded lamp sessions. The first began before midnight; only its portion inside today belongs in today’s total. This is arithmetic to explain the settings, not a claim about a real household.

After the final switch-off, the expected Time result is 135 ÷ 60 = 2.25 hours. Likewise, 1.50 hours means 90 minutes, not one hour and fifty minutes. Period clipping and matching-state accumulation follow the History Stats calculation.

If you create another helper with Type Count, this example has three matching on-periods, even though only two switch-ons happened after midnight. The already-on session at the start also counts. Choose Time for duration; do not read Count as hours or assume it is a strict count of today's button presses.

4. Rehearse without controlling an appliance

Use a separate Toggle helper as a pretend lamp. It changes only its own value unless you connect it to an automation. Leave it unconnected to device actions.

  1. Create a Toggle helper named Runtime practice. Set it off and confirm its changes appear in History.
  2. Create another History Stats helper using the daily settings above, but select this Toggle as the source. Note its starting total; a new, previously unused source should be near zero.
  3. Turn the Toggle on for three minutes, off for one minute, then on for another three minutes. Turn it off again. Avoid crossing midnight during this rehearsal.
  4. Allow the next update. The total should have increased by about 0.10 h: six on-minutes divided by sixty. The intervening off-minute should not count.
  5. Leave it off for another minute. The daily total should stay steady. Then compare your real lamp’s total with its History timeline before relying on it.

History Stats updates when the source changes and otherwise about once a minute. Allow for that cadence and your timing; this is not a stopwatch calibration. If your source history is absent, fix recording first rather than repeatedly recreating the helper.

5. Keep older daily summaries without pretending history is unlimited

Recorder is the part of Home Assistant that saves state history. Its default detailed-history retention is ten days. Asking History Stats for the last thirty days does not create the missing twenty days. Review the source’s inclusion in Recorder and the retained period before interpreting a long total. The Recorder documentation describes the filters and retention setting.

For future daily comparisons, the daily Total increasing helper above can produce long-term statistics if that new sensor is also recorded. Home Assistant stores these hourly summaries separately from the original on/off events. A new sensor’s initial reading becomes a baseline: do not assume its first partial day backfills all earlier runtime. See long-term statistics.

Once statistics exist, an optional Statistics graph card can show daily changes as bars. In an editable dashboard, add a Manual card and paste the following, replacing the example sensor ID with your actual helper’s ID:

type: statistics-graph
title: Reading lamp runtime by day
entities:
  - sensor.reading_lamp_on_today
stat_types:
  - change
period: day
chart_type: bar
days_to_show: 7

The bars summarize accumulated recorded on-time, not electrical consumption. They do not restore purged switch events or prove what happened while Home Assistant was offline. Keep the raw source history available while checking the first complete days. Before increasing retention substantially, review the Recorder storage guide; this setup does not require deleting history or disabling automatic cleanup.

Common questions

Do I need an automation to reset the total at midnight?

No. With Start set to today’s midnight and End to now, the measurement window moves to the new day automatically. You do not need a midnight reset automation or a Utility Meter solely to reset this display.

Will it know what happened during a Home Assistant outage?

Do not assume so. It calculates from available recorded states, not an independent physical runtime meter. Missing changes during an outage limit the result. A restart is not a reason to discard the history that was successfully recorded.

Does this keep everything local?

The calculation happens in Home Assistant. The source device may still depend on a vendor cloud to report its state. Saving runtime also creates a record of household activity; consider that before tracking occupancy or individual people.

Our recommendation is to start with one clearly named device and a visible source timeline. If you are planning the wider system, Tara’s configured Home Assistant setup explains the setup path. Agree on what each reading actually represents before using it to make household decisions.
