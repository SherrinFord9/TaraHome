Home Assistant Filter Sensor: Smooth Noisy Readings

Choose the right filter, keep the original reading visible, and check what smoothing changes before a routine depends on it.

By Tara Home

TLDR

  • For small, frequent fluctuations, start with the built-in Filter helper and Lowpass. It creates a separate, smoother sensor; keep the original reading visible.
  • Match the fix to the problem. A smoother graph, an isolated bad reading, and an automation switching repeatedly near a threshold need different solutions.
  • Smoothing trades responsiveness for steadiness. Lowpass does not run on a seconds-based countdown, and a quiet source can leave its output behind.
  • Compare both readings before changing any automation. Do not smooth urgent alarms or hide an unavailable sensor just to make a chart look tidy.

Start with a second reading you can compare

A Home Assistant filter sensor is useful when one numeric reading jumps around and you want a steadier value. Start with a modest Lowpass filter for everyday room-temperature display. This blends each incoming value with the previous filtered result. It does not calibrate the thermometer or establish which reading is true.

First decide whether you want to change the number or only its appearance. A dashboard’s averaged graph can look calmer while your automation still receives the original sensor. Conversely, creating a Filter helper does not redirect existing automations: they keep using whichever entity you selected. An entity is Home Assistant’s name for one reading or control.

Our recommendation is to compare the raw and filtered readings on a dashboard before using the new value elsewhere. If a fan or heater keeps switching around one boundary, first consider separate on and off thresholds. Filtering the input can add delay without fixing the switching rule. The Threshold helper calls that separation hysteresis.

1. Choose the smallest change that solves the problem

Look at the original sensor’s recent history. Note whether you see frequent small changes, occasional implausible jumps, or long gaps. Check its placement and manufacturer’s instructions before assuming the data needs filtering.

2. Add a Lowpass helper beside the original sensor

You need a working numeric sensor entity and an account that can create helpers. No extra device, paid subscription, app or custom integration is required for this calculation. The original device’s connection still has its own requirements.

  1. Open Settings → Devices & services → Helpers → Create helper → Filter.
  2. Name it something explicit, such as Living room temperature smoothed. Select the original room-temperature sensor as the input.
  3. Choose Lowpass. For this demonstration, set Time constant to 4, Precision to 2, and leave Window size at 1. These are learning settings, not a universal thermostat recommendation.
  4. Save. Find the new entity and add it beside the original reading on a dashboard. A new helper may need recorded starting data or a normal source update before it has a value. Once both readings are available, confirm they show the same temperature unit.
  5. Leave existing automations on their original inputs while you compare the two. Record the exact new entity ID if you later choose to use it.

The current Filter documentation describes the helper route. The checked 2026.10.2 configuration flow exposes these Lowpass settings and accepts sensor entities. Older versions may use different labels. If Filter is missing from your helper list, check your installed version before following an older YAML-only tutorial.

Time constant 4 does not mean four seconds. At each processed input, this example keeps three quarters of the previous filtered value and adds one quarter of the new reading. A larger constant gives the newest reading less influence. Two decimal places make the demonstration easier to follow; they do not make the physical sensor more accurate.

3. Read a worked example before trusting the result

Imagine the raw and filtered temperatures have already settled at 20.00°C. The following source changes arrive in order, with no extra updates between them. With Time constant 4 and Precision 2, the calculation is:

New filtered value = (previous filtered value × 0.75) + (new raw value × 0.25), rounded to two decimal places for each step.

The last row matters for sensors that report only changes. The built-in filter listens to source state-change events; it is not continuously moving toward the last number on its own clock. An attribute change can also produce a source state-change event. Actual results depend on the events your integration supplies, as well as the starting history. The Filter implementation defines that update path and calculation.

Do not inject random numbers into a measurement to make it look active. If a stable input must be represented directly, keep the raw value for that purpose. If you need a time-based statistic, choose and verify that calculation explicitly instead of treating Lowpass as a timer.

4. Verify it without switching equipment

  1. Keep this a display-only check. Open both entities’ history and current values. Do not change a thermostat target, heat a freezer sensor, or edit a real sensor’s state to create a test.
  2. Observe several normal updates. Expect the filtered reading to move less abruptly than the raw one. After a real sustained change, expect some lag. Immediately after creation or restart, starting history can affect the comparison.
  3. Check one calculation. Note the previous filtered value and next raw value, then use the formula above. If your result differs, inspect intervening state or attribute updates before changing settings.
  4. Check a quiet period. If there are no source state-change events, a Lowpass output can stay behind the displayed raw value. Decide whether that behavior is acceptable for your intended use.
  5. Keep a clear way back. Leaving the helper unused by automations makes this trial reversible. If you later select it in a routine, document the original entity so you can restore that input.

There is no need to restart the house or delete recorded history for this comparison. A smoother line alone is not a pass: the result must still represent changes quickly enough for the job. If the difference is hard to judge, continue using the original sensor.

Common questions

Should I add Outlier and Lowpass together?

Only if you have identified both isolated bad samples and ordinary fluctuations. The UI configures one filter per helper; YAML can apply a chain in its listed order. Start with one so you can see what it changes. Outlier needs enough previous samples for its comparison, and a real abrupt change can resemble an error. Do not copy somebody else’s radius without checking the unit and normal range.

Will this reduce my database size?

Creating a second entity is not a database cleanup. The original sensor can still be recorded, as the Recorder reference explains. Throttle filters skip samples; they do not average them or automatically exclude the original from Recorder. Keep storage changes separate from this display trial.

Can I use the smoothed value for heating or an urgent alert?

Do not move an urgent alert onto a slower or spike-rejecting input just to reduce noise. Heating also needs appropriate equipment controls, failure behavior and cycling limits. This guide verifies a calculated display; it does not validate a heating controller or replace a certified alarm.
