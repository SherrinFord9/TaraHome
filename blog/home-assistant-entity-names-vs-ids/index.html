Home Assistant Entity Names vs IDs: Rename Safely

Choose the right field for a clearer dashboard, keep working references intact, and check one harmless example before tidying the rest.

By Tara Home

TLDR

  • For a clearer label on one dashboard, change the card name. Leave its selected entity and entity ID alone.
  • For a clearer device name throughout Home Assistant, rename the device. Name each entity for its function, such as Temperature. Existing ID-based references can stay as they are.
  • Do not use “Recreate entity IDs” just to tidy the screen. An ID change needs a review of automations, scripts, dashboards and external tools that refer to the old ID.
  • On 2026.11, longer names can be a display change. Check the ID before repairing anything. Start with the card-only exercise; name-based templates and automations watching attribute changes need review before renaming a device.

Change the name people see first

Home Assistant entity names and IDs serve different jobs. A name helps somebody recognize a control or reading. An entity ID, such as sensor.sensor_04_temperature, is the reference used in configuration. An entity is one function: a temperature reading, battery level or on/off control. One physical device can provide several.

If the complaint is “this dashboard label is too long,” edit that card’s name first. If the whole device has an unhelpful name, rename the device. Keep a working entity ID unless you have a specific reason to change it. The entity settings documentation treats the name and ID as separate fields.

Home Assistant 2026.11 changed how it combines names with their context. A screen can include the device or room even when the entity name is simply Temperature. The November naming explanation says existing entity IDs remain unchanged. A different-looking label alone does not mean the automation lost its target.

A unique ID is another identifier, supplied by the integration—the connection between Home Assistant and a device or service. It helps Home Assistant recognize the same entity internally. It is not a prettier display name and is not the field to edit for this job. The unique ID FAQ explains why some manually configured entities cannot be renamed through the interface.

1. Rehearse with two temperature cards

Use an existing room-temperature sensor and a dashboard you already manage manually. This exercise only changes presentation. If you need a practice dashboard, follow the Sections dashboard setup. Do not take control of an automatically managed dashboard just for this exercise: the Tile documentation explains that doing so stops its automatic updates.

  1. Open Settings → Devices & services → Entities. Select the temperature reading and open its settings. Copy its exact entity ID into a private note.
  2. On the practice dashboard, add two built-in Tile cards and select that same sensor for both. Leave the first card’s name at its default.
  3. For the second card, set a custom name of Desk temperature. Keep the same selected entity. Save the card and dashboard.
  4. Check that both cards show the same sensor reading after they update. Open each card’s information dialog and confirm the underlying entity is the same. The second card should have your custom title.
  5. Remove the second card’s custom name to return to its default, or remove the temporary cards. Neither step deletes the sensor.

Here is the second card in YAML, the text form of its settings. Replace the example ID with yours. Both tap actions open information; they do not send a device command.

type: tile
entity: sensor.sensor_04_temperature
name: Desk temperature
tap_action:
  action: more-info
icon_tap_action:
  action: more-info

The card naming reference also supports composing a name from parts, such as device and entity. A fixed custom string is the easiest first check. It stays fixed even if the device is later renamed, so review it whenever the device changes purpose.

3. Apply the name change and verify it

Check what watches this device before renaming it. A name change can alter an attribute such as friendly_name. A State changed trigger without From/To restrictions can react to attribute-only changes. Keeping the ID does not prevent that run. Use a non-critical monitoring sensor for this exercise; if it feeds heating, security or another consequential routine, finish the dependency review first and keep the initial test card-only.

  1. Open Settings → Devices & services → Devices, select the intended device and use its edit control to change the device name to Desk sensor.
  2. If an individual reading also needs a clearer name, open that entity’s settings and change its name. Leave the recorded entity ID unchanged. Select Update.
  3. Reopen the entity settings and compare the ID with your note character for character. Check the default Tile card and your custom-named card. The default can reflect the new device context; the custom title should remain Desk temperature.
  4. Inspect an existing automation that uses this sensor. Its entity reference should still match. Observe its next harmless normal run if appropriate; do not manually run heating, locks or other consequential actions just to test a rename.

You can inspect the reported reading under Settings → Tools → States; older versions use Developer tools. Read the existing row without using Set state. The state documentation explains the distinction between the reading and descriptive attributes.

Check name-dependent templates separately. A template is an expression that builds text or selects data. If yours compares or searches names, a display rename can change its result even when the ID stays intact. A notification using friendly_name can also show different wording. The November announcement says that attribute is retained for compatibility for now; it has not simply disappeared.

4. If you already changed an entity ID

Treat this as repairing references, not fixing the physical device. Do not reset or re-pair it. Home Assistant’s automation troubleshooting guide describes old entity references remaining after an ID change.

  1. Record the old and current IDs. Before further ID changes, make a backup using the backup and restore guide.
  2. Open affected automations and reselect the current entity in every relevant trigger, condition and action, then save. Also check scripts, scenes and manually configured dashboard cards.
  3. Search your own YAML, templates and external tools, such as Node-RED, for the exact old ID. A visual picker check does not audit those files or flows.
  4. For each repaired reference, use a harmless reading or informational preview first. Review the automation trace—the record of its run—when an appropriate normal trigger next occurs.

Do not bulk-recreate IDs to repair one name. If you deliberately want a new ID scheme, migrate one non-critical entity at a time with a before/after list. If the hardware itself was replaced, use the separate device replacement guide; device-based references add another issue.

Common questions

Will changing the entity ID format rename everything?

No. It applies when Home Assistant generates new IDs. Existing IDs stay put unless you change or recreate them. Leave working IDs in place when your goal is only a tidier display.

Can I keep an inventory name and a different dashboard name?

Yes. Keep the device name you need for inventory and set a custom name on the relevant card. That card title is local to the card; it is not a universal name for notifications or other dashboards.

Does renaming make a cloud device local?

No. Naming changes presentation and references. It does not change the integration or the device’s network and account requirements.
