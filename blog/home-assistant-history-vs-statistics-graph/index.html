Home Assistant History Graph vs Statistics Graph

Build two useful views of one room: what happened today, and how its temperature changed over a month.

By Tara Home

TLDR

  • Use History graph for recent events: compare room-temperature changes with a window’s open/closed timeline.
  • Use Statistics graph for longer trends: show daily minimum, maximum and average temperatures over a month.
  • Older History graphs can use statistics too. Their older line may represent hourly summaries, not every recorded reading.
  • Check the sensor before changing storage. Statistics need a numeric sensor with the right classification that Home Assistant records. Adding a graph cannot recover readings that were never saved.

Researched from current Home Assistant documentation on October 23, 2026. The configurations and temperature calculation below are worked examples, not measurements from a Tara installation or a live Home Assistant test. The cover is an illustrative generated scene.

1. Choose the graph for the question

To choose between Home Assistant’s History graph and Statistics graph, start with the question you want the picture to answer. “Did the room cool after the window opened?” needs recent readings and an open/closed timeline. “How warm did this room get each day?” needs daily summaries. Use History graph for the first and Statistics graph for the second.

Both are built into Home Assistant. You do not need a custom dashboard download or a Statistics helper just to draw these charts. A card is a panel on your dashboard; an entity is one named reading or control, such as sensor.living_room_temperature.

The distinction is not simply short history versus long history. The History graph documentation says older sections can be filled with hourly statistics when detailed readings are no longer retained. Statistics graph lets you choose the summary and time interval explicitly.

2. Check one room before adding cards

  1. Choose an existing temperature sensor. Open its details and copy its entity ID. You need a working numeric reading with a temperature unit, such as °C or °F. If you have a window contact sensor, copy that ID too.
  2. Open History and select the temperature entity. Choose a recent range with data. Confirm you are looking at the intended room. Current versions offer Sources → Add target; older versions may label the selector differently.
  3. Check the sensor’s classification. In Settings → Tools → States, inspect its attributes without changing them. Older versions call this area Developer tools. An ordinary room-temperature sensor should have state_class: measurement. A name beginning with sensor. is not sufficient by itself.
  4. Check Statistics for reported issues. The current path is Settings → Tools → Statistics. A numeric sensor must also be included in Recorder, Home Assistant’s history storage. A recorder exclusion can prevent new statistics even when the live reading looks fine.

The statistics requirements cover recording and numeric states. The sensor state-class reference defines a measurement. Keep the existing temperature unit; do not change classifications or units merely to make a picker accept the entity.

3. Add two cards for the same temperature

Use a dashboard you already edit, or a separate dashboard for this trial, with an account allowed to edit it. Open Edit dashboard → Add card. Choose the card type, then its code editor to enter the example. These are card configurations, not entries for configuration.yaml. The card instructions describe the different Add card locations for Sections and other layouts. If an automatically managed dashboard asks you to take control, use a separate editable dashboard if you want to preserve its automatic updates.

A recent “what happened?” view

Choose History graph. Replace both entity IDs with yours. If you have no window sensor, remove its two-line entry.

The code examples scroll sideways on a narrow screen.

type: history-graph
title: Living room — last 24 hours
hours_to_show: 24
entities:
  - entity: sensor.living_room_temperature
    name: Room temperature
  - entity: binary_sensor.living_room_window
    name: Window

Expect a temperature line and a separate window-state timeline. They are different kinds of information, not two numbers on one scale. The source devices decide how often readings arrive; this card cannot reveal a temperature change between unrecorded samples.

A monthly “how did the room behave?” view

Add a Statistics graph using the same temperature entity. The example requests one daily set of summaries across the last 30 days:

type: statistics-graph
title: Living room — daily temperature range
days_to_show: 30
period: day
chart_type: line
stat_types:
  - min
  - max
  - mean
entities:
  - entity: sensor.living_room_temperature
    name: Room temperature

min means the lowest recorded value, max the highest, and mean the average. The Statistics graph reference documents these options. A wider gap between low and high means a bigger recorded swing. Today’s values describe a day still in progress, so compare completed days when judging a change to the room.

If the sensor has only existed for three days, a 30-day card will not invent the other 27. For a newly eligible sensor, allow statistics to accumulate through completed reporting intervals before expecting a useful daily view.

4. Understand why the lines differ

Consider this hypothetical recorded hour, with no missing readings: the temperature stays at 20°C for 50 minutes, then stays at 24°C for 10 minutes. Home Assistant’s measurement average is weighted by duration. It is not the simple average of the two numbers.

Hourly mean = (20 × 50 + 24 × 10) ÷ 60 = 20.67°C.
The recorded minimum is 20°C and the maximum is 24°C.

This is a calculation, not a measured room test. Scroll sideways on a narrow screen.

The measurement statistics documentation explains the time weighting. The History data-source explanation describes the older hourly averages and the darker line used for recent detail. A calmer-looking line is not evidence that the sensor became more accurate.

The monthly card above uses period: day, so it combines more than this single hour. Temporarily set it to hour if you want to inspect one completed hour. Do not compare a daily average directly with one instantaneous reading and call the difference an error.

5. Verify the cards without changing the house

  1. Wait for ordinary readings. Leave heating, windows and existing routines alone. Do not overwrite a real sensor’s state to make a test point.
  2. Compare the recent card with History. Select the same entity and time window in the History panel. A recorded temperature change should appear in both. A window timeline should agree with its recorded state changes.
  3. Inspect a completed hour. Temporarily use period: hour on the Statistics graph. Its mean should fall between its minimum and maximum. Compare with the detailed record, not just the current value.
  4. Restore the monthly view. Set period: day again. Keep minimum and maximum visible if brief warm or cold periods matter. Remove either trial card to undo the dashboard change.

This verifies the display against recorded data; it does not calibrate the physical sensor. Check gaps before interpreting an average: a day with missing readings is not a complete record of the room. A chart also cannot prove that an unchanged value is fresh. If you need the underlying data for closer inspection, History offers Menu → Download data. An export of an older summarized period still cannot restore discarded detailed readings.

Common questions

Do I need a Statistics helper first?

No. The Statistics graph card reads saved statistics for eligible sensors. The separate Statistics helper creates a new calculated sensor from a buffer of recent values. Its sample capacity and age settings matter; seeing an older chart does not mean that helper has the same underlying samples.

Will the average change my heating automation?

No. Selecting a graph’s mean changes what the card displays. It does not replace the entity used by a routine. If you deliberately want a different input, our sensor filtering guide explains the added lag and why the original reading should remain available.

Should I install a custom chart?

Start with these native cards. Consider a custom chart only when you can name the missing feature, such as a particular comparison layout. A different chart cannot supply measurements that Home Assistant never received or retained.
